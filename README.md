# 생필품 가격 에이전트

사용자가 채팅으로 물으면 LLM이 질문을 해석해 공공 API를 호출하고, 필요한 생필품 가격 정보를 찾아 설명해 주는 웹 서비스입니다. 데이터는 한국소비자원 [참가격 생필품 가격 정보 API](https://www.data.go.kr/data/15158701/openapi.do)입니다.

> **상태: 기획 단계.** 아직 코드는 없습니다. 지금 상황·담당·PM 승인 대기는 **[docs/STATUS.md](docs/STATUS.md)**에 있습니다.
> 이전 컨셉(청년 정책 안내 에이전트)은 `archive/youth-policy` 브랜치에 있습니다. 컨셉을 바꾼 이유는 [D1](docs/decisions/D1.md)에 있습니다.

- **대상 사용자**: 미정 — API 데이터를 분석한 뒤 정합니다
- **형태**: 회원 정보를 저장하지 않는 웹 채팅 서비스
- **목적**: FDE·IT 기업 지원용 포트폴리오, LLM 에이전트 학습

## 왜 만드나

생필품 가격은 이미 공개돼 있습니다. [참가격](https://www.price.go.kr/tprice/portal/main/main.do)은 전국 주요 유통업체의 생필품 가격을 매주 조사해 공개하고, 같은 데이터가 공공데이터포털 API로 무료 제공됩니다.

참가격 사이트에도 장바구니 가격 비교가 있지만, 상품을 하나씩 검색해 담고 비교할 판매점을 직접 골라야 합니다. "30명 워크숍 장보기"처럼 머릿속의 상황을 그대로 말해서는 답을 얻을 수 없습니다. 이 프로젝트는 그 간극을 대화로 메웁니다.

## 서비스 흐름

1. 사용자가 채팅으로 질문합니다.
2. LLM이 의도를 해석하고, 필요한 조건이 모일 때까지 선택지로 되묻습니다.
3. 조건이 모이면 서버가 참가격 API를 호출합니다. 검색어는 사용자 문장이 아니라 LLM이 뽑은 키워드만 보냅니다.
4. 서버가 응답을 조건에 맞게 걸러 내고 계산합니다. 무엇을 계산할지(단가 비교, 총액 등)는 타깃이 정해진 뒤 정합니다.
5. LLM이 결과를 사용자에게 설명합니다.

## 개인정보 원칙

| 항목 | 원칙 |
| --- | --- |
| 대화 저장 | 브라우저 `sessionStorage`만 사용. 탭을 닫으면 사라짐. 서버 DB 저장 없음 |
| LLM 전송 | 선택지로 받은 값만 LLM에 보냄 |
| 서버 로그 | 채팅 내용과 선택값을 남기지 않음 |
| 공공 API 검색어 | 사용자 문장을 그대로 넣지 않고 LLM이 뽑은 키워드만 보냄 |
| API 키 | `.env`에 두고 커밋하지 않음 ([키 관리](#api-키-관리)) |

참가격 API의 요청값은 조사일, 업체ID, 상품ID, 코드 분류뿐이라 사용자 정보가 정부 API로 가지 않습니다. 판매점 좌표를 써서 "내 주변 마트" 기능을 넣으면 사용자 위치를 받게 되므로, 그때 위치 처리를 다시 정합니다.

## 공공 API

[한국소비자원_생필품 가격 정보](https://www.data.go.kr/data/15158701/openapi.do) — 무료, 자동승인, 개발계정 트래픽 2,000, 응답 XML. 공공누리 1유형이라 출처 표시가 필요합니다.

| 오퍼레이션 | 요청 | 주요 응답 |
| --- | --- | --- |
| 기준정보 `getStandardInfoSvc.do` | 코드 분류(`classCode`) 필수 | 단위, 용량, 상품분류, 업태, 지역 코드표 |
| 판매점 `getStoreInfoSvc.do` | 없음 = 전체, `entpId` = 한 곳 | 업체명, 업태·지역 코드, 주소, 전화, X·Y 좌표 |
| 상품 `getProductInfoSvc.do` | 없음 = 전체, `goodId` = 하나 | 상품명, 소분류, 제조사, 용량·단위량과 단위 |
| 가격 `getProductPriceInfoSvc` | 조사일(매주 금요일) 필수 + 업체ID 또는 상품ID | 가격, 할인 여부·기간, 1+1 여부 |

가격은 한 번에 전체를 받을 수 없어 판매점별 또는 상품별로 나눠 불러야 합니다. 판매점 수에 따라 하루 2,000건 안에서 나눠 받는 계획이 필요합니다.

## 저장소 구조

```
.
├── docs/
│   ├── STATUS.md          # 지금 상태·할 일·담당·PM 승인 대기 (작업 시작점)
│   ├── decisions/         # PM이 승인한 결정 — 하나에 파일 하나 (D1, D2, …)
│   ├── log/               # 한 일 — 작업 한 건에 파일 하나 (001, 002, …)
│   ├── process/           # 작업 규칙, 마무리 절차
│   └── reference/         # 기획 제안서 원문
├── experiments/           # 실험·측정 (데이터 분석 계획이 정해지면 추가)
├── AGENTS.md              # AI 코딩 도구 공통 규칙
├── CLAUDE.md              # Claude Code용 — AGENTS.md를 불러옴
├── .claude/settings.json  # Claude Code가 .env를 읽지 못하게 차단
├── .gemini/settings.json  # Gemini CLI가 AGENTS.md를 읽게 설정
└── .env.example           # 필요한 환경변수 목록 (값 없음)
```

문서 지도와 작업 흐름은 [docs/README.md](docs/README.md)에 있습니다. 코드 디렉토리는 기술 스택이 정해지면 추가합니다.

## API 키 관리

1. `.env.example`을 복사해 `.env`를 만들고 각자 발급받은 키를 넣습니다.
   ```bash
   cp .env.example .env
   ```
2. `.env`는 `.gitignore`에 들어 있어 커밋되지 않습니다. 키는 저장소 밖(팀 메신저 등)으로 공유합니다.
3. **ChatGPT·Claude 같은 채팅 AI에 키나 `.env` 내용을 붙여넣지 않습니다.**
4. AI 코딩 도구용 규칙은 [AGENTS.md](AGENTS.md)에 있습니다. 실제로 `.env` 읽기를 막는 건 Claude Code(`.claude/settings.json`)뿐이고, 다른 도구에는 지시문으로만 적용됩니다.

## 미정 사항

타깃 사용자와 구체 기능, 데이터 분석 방법, 핵심 변수, 위치 기능, LLM 업체·팀 구성, 기술 스택이 미정입니다. 목록과 진행은 [STATUS "PM 승인 대기"](docs/STATUS.md#pm-승인-대기-승인-전-착수-금지)에서 관리합니다.

실질 개발 기간은 4~5주이며, 주차별 계획은 미정입니다.

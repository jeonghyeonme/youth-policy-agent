# 생필품 가격 실측

생필품 가격안은 시험이 하나도 없어 3안 점수표의 정확성·토큰이 추정이었다. 두 단계로 잰다.

1. **데이터 조사 (`collect.py`)**: 참가격 API를 30회 안팎 불러 판매점·상품·가격 데이터가 실제로 어떤지 본다. 제안서가 "데이터 분석으로 확인"하기로 한 것(업태별 판매점 수, 소모품 존재, 할인·1+1 채움 정도)도 여기서 나온다.
2. **질문→답 실측**: 1단계에서 확인한 실제 필드로, 청년 정책([youth-e2e](../youth-e2e/README.md))·법률 정보와 같은 조건(Groq gpt-oss-120b, 질문당 LLM 2회)의 스크립트를 만든다.

## 1단계 실행

준비: 공공데이터포털에서 [한국소비자원_생필품 가격 정보(15158701)](https://www.data.go.kr/data/15158701/openapi.do) 활용신청. 자동승인이다. 키는 다른 공공데이터포털 서비스와 같은 `DATA_GO_KR_SERVICE_KEY`(Decoding 키)를 쓴다.

```bash
python3 experiments/grocery-e2e/collect.py
```

- 결과 요약은 `survey.json`, 받은 응답은 `cache/`에 저장된다. 둘 다 공개 데이터라 커밋해서 공유한다. 키는 저장하지 않는다.
- 두 번째 실행부터는 cache를 읽어 API를 부르지 않는다.
- `[API 오류]`가 나오면 활용신청 승인 전이거나 키가 다른 것이다. 그 줄을 그대로 공유하면 된다(키는 들어 있지 않다).

## 확인할 것

| 항목 | 왜 |
| --- | --- |
| 판매점 수, 업태·지역 분포 | 대형마트 위주인지, 편의점이 있는지 (제안서의 미확인 사항) |
| 상품 수, 소모품(화장지·종이컵·커피믹스·생수) 존재 | 탕비실 시나리오가 가능한지 |
| 가격 필드와 채움률 | 할인·1+1을 실제로 쓸 수 있는지 |
| 상품당 가격이 있는 판매점 수 | "한 곳에서 다 살 때 가장 싼 곳" 계산이 되는지 |
| 최신 조사일 | 매주 금요일 조사가 실제로 몇 주 전 것인지 |

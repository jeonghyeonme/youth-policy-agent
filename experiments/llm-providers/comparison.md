# 무료 LLM API 비교 (Q5)

> 2026-10-29 조사 · 관련: Q5, [D3](../../docs/decisions/D3.md) · 숫자는 바뀌므로 신청 전에 각 콘솔에서 다시 확인한다.
> 출처 표시: **공식**은 업체 문서를 직접 읽은 것, **제3자**는 블로그·비교 사이트가 전한 것이다. 제3자 숫자는 사이트마다 달랐다.

## 우리 쪽 조건

- D3에 따라 질문 하나에 LLM을 최대 2회 부른다. 1회차는 사용자의 첫 자유 문장을 조건 코드(JSON)로 바꾸고, 2회차는 걸러진 정책 몇 건을 설명한다.
- **1회차에는 사용자가 쓴 문장이 그대로 간다.** 2회차에는 선택값(나이, 지역 등)과 공개 정책 텍스트가 간다. 그래서 입력 데이터를 학습이나 사람 검토에 쓰는지가 한도만큼 중요하다.
- 팀원이 한 키를 같이 쓴다. 한도는 키가 아니라 조직이나 프로젝트 단위로 세므로, 키를 여러 개 만들어도 늘지 않는다(Gemini, Groq 공식).

## 하루에 받을 수 있는 질문 수 (추정)

질문 하나는 LLM 2회다(D3). 토큰은 아직 재지 않았다(W6). 아래는 질문 하나에 입력·출력을 합쳐 3K~6K 토큰을 쓴다고 **가정**한 계산이다.

| 업체 | 요청 수 기준 | 토큰 기준 | 실제 상한 |
| --- | --- | --- | --- |
| Groq | 1,000회 ÷ 2 = 500개 | 200K ÷ 3K~6K = 33~66개 | **토큰이 먼저 막힌다. 하루 약 33~66개** |
| OpenRouter 무료 | 50회 ÷ 2 = 25개 | - | 25개 |
| Gemini 무료 | 제3자 숫자로 약 750개 | - | 숫자가 공식이 아니다 |

Groq의 상한은 토큰 수에 거의 정비례한다. LLM에 넘기는 정책 수와 필드를 줄이는 것(W6)이 곧 하루 질문 수를 늘리는 일이다. 데모와 팀 개발에는 충분하지만, 공개 서비스로 열면 부족할 수 있다.

## 추천

1. **Groq를 주 업체로 한다.** 무료 업체 중 입력 데이터를 기본으로 보관하지 않는 곳은 확인한 범위에서 Groq뿐이다. 1회차에 사용자 문장이 가는 우리 구조에 맞는다. 가입 후 무보관(ZDR)을 켠다.
2. **Mistral을 예비로 둔다.** Groq 한도를 다 쓰면 넘긴다. 가입 직후 학습 사용을 끈다.
3. 둘 다 막히면 D3대로 LLM 없이 결과 카드만 보여 준다.
4. Gemini는 사용자 문장이 가는 호출에 쓰지 않는다.

## 정하기 전에 시험할 것

한국어 품질과 JSON 출력은 문서로 알 수 없다. 키를 받으면 같은 질문 10개로 시험한다.

- 1회차: 자유 문장을 조건 코드 JSON으로 바꾼다. JSON이 형식에 맞는 비율, 분류가 맞는 비율을 센다.
- 2회차: 정책 3건 설명. 한국어가 자연스러운지, 서술형 자격조건을 지어내지 않는지 본다.
- 질문마다 쓴 토큰을 기록해 위의 3K~6K 가정을 실제 값으로 바꾼다(W6).

호출은 업체마다 약 20회다. 실행은 사람이 한다(AGENTS.md "API 키").

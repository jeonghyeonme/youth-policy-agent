# Q3 추천안: LLM에 넘길 정책을 고르는 기준 (2026-11-08)

> [측정 계획](README.md) · STATUS Q3 · **AI가 올린 추천안이다. 결정은 PM이 한다.**
> 실험: `python3 experiments/context-measurement/rank_experiment.py` (저장된 샘플만 쓴다. API 호출 없음)

## 왜 정해야 하나

- 대표 질문 A(종로구·26살·미취업)는 지역·나이·취업으로 걸러도 약 160건이 남는다([결과](results.md#온통청년-지역-필터-2026-11-08-확인)).
- 정책 1건은 약 280토큰이다. 무료 한도가 분당 8,000토큰이면 한 번에 15건 안팎밖에 못 넘긴다([Groq 조사](groq-models.md)).
- 그래서 **"무엇을 넘기느냐"가 답변 품질을 가장 크게 좌우한다.** 이게 Q3(핵심 변수)의 실질적인 내용이다.

## 실험: 순위 기준 6가지를 샘플에 돌려 봤다

순서: ① 서버 필터(지역·나이·취업) → ② **신청 가능**(마감 제외) → ③ 순위 → 상위 10건.

| | A: 종로구 26살 미취업, "지원금" | B: 서울 27살 자취, "월세" |
| --- | --- | --- |
| 받은 건수 | 100 (전체 297 중 첫 페이지) | 100 |
| ① 조건 통과 | 53 | 11 |
| ② 신청 가능 | **25** | **6** |

| 순위 기준 | A 상위 10건 중 키워드 일치 | A 상위 10건 중 서울 정책 | B에서 "청년 월세 지원"의 순위 |
| --- | --- | --- | --- |
| API 순서(최신 등록) | 4 | 4 | 5위 |
| 조회수 | 6 | **0** | 1위 |
| 마감 임박 | 6 | 4 | 3위 |
| 지역 전용 우선 | 4 | 4 | 4위 |
| 키워드 일치 | **10** | 2 | **1위** |
| 조합(키워드×2 + 맞춤 + 지역, 동점은 마감·조회수) | **10** | 2 | **1위** |

## 알게 된 것

1. **"신청 가능" 필터만으로 절반이 줄어든다.** A는 53 → 25건. 마감된 정책은 순위를 매기기 전에 빼야 한다.
2. **질문과 맞는지(키워드)가 가장 잘 고른다.** B에서 사용자가 찾는 "청년 월세 지원"을 1위로 올린 것은 키워드 일치와 조합뿐이었다. 조회수는 서울 정책을 하나도 못 올렸다(전국 정책이 조회수가 높다).
3. **그런데 글자 맞추기는 거칠다.** A에서 "수당"이 "게임사 현장교육"(참여 수당)에도 걸렸다. 10건이 모두 일치 1개라 순위가 잘 갈리지 않았다. 더 좋은 좁히기가 필요하다.
4. **B처럼 건수가 적으면 순위는 거의 상관없다.** 거른 뒤 6건이면 다 넘기면 된다.
5. 샘플 한계: 받은 첫 100건만 봤고, 종로구 전용 정책은 하나도 없었다. 지역 전용 우선은 제대로 시험되지 않았다.

## 추천: 3단계로 고른다

| 단계 | 하는 일 | 누가 |
| --- | --- | --- |
| 1. 요청 좁히기 | LLM이 질문에서 **정책 키워드**(코드정의서의 17개, 예: 보조금·주거지원)와 **중분류**를 고르고, 서버가 그 값으로 API를 부른다 | LLM이 고르고 서버가 호출 |
| 2. 서버 필터 | 지역(API `zipCd`) → 나이·취업 요건 → **신청 가능(마감 제외)** | 서버 |
| 3. 순위 | 키워드 일치 → 지역 전용(구 > 시도 > 전국) → 마감 임박 순으로 **상위 8건**만 LLM에 넘긴다(약 2,300토큰). 나머지는 "N건 더 있음"과 목록 링크로 알린다 | 서버 |

- **8건인 이유**: 분당 8,000토큰 기준으로 정책 데이터에 약 2,300토큰을 쓰면, 시스템 프롬프트·도구 정의·대화 기록·답변에 5,000토큰 넘게 남는다(가정). 무료 한도가 더 넉넉하면 늘린다.
- **1단계는 동작한다(2026-11-08 실측).** 종로구·일자리 297건에서 `plcyKywdNm=보조금`은 **73건**(모두 보조금 키워드), `mclsfNm=취업`은 188건이 나왔다.

## 3단계를 모두 적용한 결과 (질문 A)

| 단계 | 건수 | 비고 |
| --- | --- | --- |
| 지역(종로구)·대분류(일자리) | 297 | API |
| ① + 정책 키워드 `보조금` | **73** | API, 호출 1회 |
| ② 나이·취업·신청 가능 | **9** | 서버 |
| ③ 상위 8건 | 8 (약 2,300토큰) | 9건이라 사실상 전부 |

- 상위에 "청년일자리도약장려금", "2026 취업날개 서비스", "청년 국가기술자격 응시료 지원" 같은 질문에 맞는 정책이 올라왔다. 1단계 없이 순위만 매겼을 때(위 표)보다 덜 엉뚱하다.
- **API 한 번 호출로 끝난다.** 297건을 페이지 3번에 나눠 받을 필요가 없다.
- 남은 문제: "고교 취업연계 장려금"이 26살 질문에 남았다. 나이 제한 표시가 "제한 없음"(`sprtTrgtAgeLmtYn=N`)이라 나이로 걸러지지 않았다. 학력 요건(고교)은 코드로 있으니 서버에서 더 거를 수 있지만, 대화에서 학력을 묻지 않으면 LLM이 설명에서 걸러야 한다(Q4와 연결).

**다른 선택지**: LLM이 직접 고르게 한다. 거른 정책 수십 건의 이름과 한 줄 요약만(건당 약 40토큰) 먼저 보내 LLM이 고르게 하고, 고른 것의 내용을 다시 보낸다. 더 정확할 수 있지만 답변 한 번에 LLM 호출이 두 번 들어 무료 한도를 두 배로 쓴다. 3단계 추천안으로 시작하고, 품질이 모자라면 이쪽을 시험한다.

**다시 볼 때**: 실제 질문으로 시험해 상위 8건에 사용자가 찾는 정책이 자주 빠질 때.

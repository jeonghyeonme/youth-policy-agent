# Q4 추천안: 서술형 자격 조건을 누가 판단하나 (2026-11-08)

> [측정 계획](README.md) · STATUS Q4 · **AI가 올린 추천안이다. 결정은 PM이 한다.**
> 실험: `python3 experiments/context-measurement/judge_experiment.py` (채점은 API 호출 없음). Groq 호출 결과: `samples/groq/judge_*.json`

## 실험

- 정책: D9 3단계로 고른 질문 A 8건, 질문 B 6건.
- 사용자: 가상 인물 2명([정답표](q4/labels.json)의 `personas`).
- 정답표: LLM 결과를 보기 전에 AI가 정책 원문을 읽고 "가능 / 불가 / 확인 필요"로 정했다.
- LLM: Groq `openai/gpt-oss-120b`, 질문마다 1회. A는 입력 3,626 + 출력 1,548토큰(이 중 추론 1,140)에 4.0초, B는 입력 1,758 + 출력 1,246토큰에 3.4초.

## 결과

| 방식 | 일치 (14건) | 신청 못 하는데 "가능"이라 함 |
| --- | --- | --- |
| LLM 단독 | 6 | **2** |
| **혼합: 서버가 코드 요건 판정 + LLM이 서술형 판정** | **8** | **0** |

LLM 단독이 틀린 8건:

| 유형 | 건수 | 사례 | 혼합에서 |
| --- | --- | --- | --- |
| 신청 못 하는데 "가능" | 2 | 돌봄보조 인력: 특화 요건(여성·수급자·장애인 등)을 무시함. 한지붕 주거공유: 학력 코드 "대졸 예정"을 "대졸"로 읽음 | **둘 다 바로잡힘**(서버 코드 판정) |
| 확인 필요한데 "불가" | 4 | 게임사 현장교육, 일자리도약장려금, 귀환 청년, 청년안심주택 | 그대로. 안심주택은 데이터의 혼인 코드(기혼)가 의심스러움 |
| 가능한데 "확인 필요" | 2 | 월세 지원, 씨앗펀드: 연봉 3천만 원이 중위소득 150% 이하인지 계산하지 못하고 되물음 | 그대로(안전한 오류) |

**잘한 것**: 기업·사업주 대상 사업 4건을 모두 "불가"로 걸렀다. 코드 필드로는 못 거르는 것이다. 판단할 수 없을 때 사용자에게 물을 질문을 알맞게 만들었다.

## 추천: 혼합 (서버가 코드, LLM이 글, 최종 확인은 사용자)

1. **서버가 코드 요건을 판정한다.** 학력·혼인·취업 요건 목록에 사용자 값이 없으면 "불가", 특화 요건(여성·수급자 등)이 있으면 "확인 필요". LLM에 맡기지 않는다.
2. **LLM이 서술형을 읽는다.** 신청 주체(개인인지 기업인지), 추가 자격, 참여 제한, 소득 기타 조건. 판단할 수 없으면 사용자에게 물을 질문을 만든다.
3. **사용자에게는 판정과 근거를 함께 보여 준다.** "신청할 수 있어 보여요 / 확인이 필요해요(질문) / 해당되지 않아요(이유)" + 원문 조건 + 신청 링크. 최종 자격은 운영 기관이 정한다고 안내한다.

**다음에 고칠 것(구현 때 시험)**
- LLM의 "불가"를 줄인다: 신청 주체가 기업·기관이거나 원문이 분명히 배제할 때만 "불가", 나머지는 "확인 필요". 위 4건 중 3건이 이쪽이다.
- 중위소득 기준표(가구원 수별 금액)를 서버가 LLM에 함께 준다. LLM이 연봉과 비교할 수 없어서 되묻던 2건을 줄인다.

## PM이 함께 정할 것: LLM에 보내는 사용자 값 (개인정보)

이 실험은 나이·지역·취업 상태 말고도 **연봉, 주택 여부, 학력, 가구 형태**를 LLM에 보냈다. 지금 원칙은 "선택지로 받은 값만 LLM에 보낸다"이고, 보내는 값을 늘리는 것은 PM 승인 대상이다(AGENTS.md "개인정보").

| 선택지 | 보내는 값 | 장단점 |
| --- | --- | --- |
| **가. 선택지 값을 늘린다 (추천)** | 소득 구간(예: "중위소득 150% 이하" 같은 버튼), 주택 여부, 학력, 가구원 수. **모두 선택지로 받고 금액·자유 입력은 받지 않는다** | 이 실험과 같은 방식이라 품질을 쟀다. 원칙("선택지 값만")은 지키되 범위가 넓어진다 |
| 나. 사용자 값을 보내지 않는다 | 지금과 같음(나이·지역·취업 상태) | LLM은 서술형을 "확인 질문"으로만 바꾸고, 사용자가 화면에서 직접 체크한다. 개인정보는 늘지 않지만 사용자 부담이 크고 품질은 재지 않았다 |

**다시 볼 때**: 실제 질문으로 시험해 "가능"이라 했는데 신청이 안 되는 사례가 나올 때.

# API 키 발급하기

> [api-survey 계획](README.md) · STATUS T2 · 2026-10-29 기준 사이트 화면으로 확인한 절차

키 두 종류를 받는다. 온통청년 인증키는 온통청년 사이트에서, 나머지는 공공데이터포털(data.go.kr) 인증키 하나로 쓴다.

## 1. 온통청년 인증키를 먼저 신청한다

온통청년은 **담당자 심사 후 승인**한다(온통청년 "오픈(OPEN) API 이용방법" 페이지). 자동승인이 아니어서 시간이 걸릴 수 있으니 가장 먼저 신청한다.

1. [온통청년](https://www.youthcenter.go.kr)에 회원가입하고 로그인한다.
2. **마이페이지 → 오픈(OPEN) API**에서 인증키 발급을 신청한다. 온통청년은 API마다 따로 신청하며, **청년정책 API 하나만 신청한다.**

   | API | 신청 | 이유 |
   | --- | --- | --- |
   | 청년정책 | 필수 | 서비스의 중심 데이터 |
   | 청년센터 | 보류 | 오프라인 청년센터 안내는 제안서 범위 밖이다. 넣으려면 PM이 범위를 정한다 |
   | 청년콘텐츠, 기본계획과제, 기본계획중점과제, 기본계획정책방향 | 신청하지 않음 | 기사·정부 계획 자료라 사용자 조건과 맞출 수 없다 |

   신청 화면에는 정책코드 API가 없다. 분류·요건 코드표는 [API코드정보.xlsx](https://www.youthcenter.go.kr/downloadform/API코드정보.xlsx)를 쓴다.
   API 목록은 2026-10-29 신청 화면 기준이다. 필요해지면 나중에 추가로 신청한다.
3. 활용 목적을 구체적으로 적는다. 내용이 부적절하면 승인되지 않을 수 있다. 예시는 다음과 같다.
   > 청년 정책 안내 웹 서비스 개발(팀 프로젝트, 학습·포트폴리오 목적). 청년정책 API 데이터를 주기적으로 수집해, 사용자가 채팅으로 입력한 조건(나이, 지역 등)에 맞는 정책을 안내합니다. 사용자 정보는 저장하지 않습니다.
4. 승인되면 마이페이지에서 키를 확인한다.

## 2. 공공데이터포털에서 서비스별로 활용신청한다

인증키는 계정당 하나다. 서비스마다 활용신청을 해야 그 키로 해당 API를 부를 수 있다. 개발계정은 자동승인이다.

1. [공공데이터포털](https://www.data.go.kr)에 회원가입하고 로그인한다.
2. 아래 페이지에서 각각 **활용신청**을 누른다.

   | 서비스 | 페이지 | 필수 여부 |
   | --- | --- | --- |
   | 잡알리오 공공기관 채용정보 | [15125273](https://www.data.go.kr/data/15125273/openapi.do) | 필수 |
   | LH 분양임대공고문 조회 (목록) | [15058530](https://www.data.go.kr/data/15058530/openapi.do) | 필수 |
   | LH 분양임대공고별 상세정보 조회 (공고문 첨부파일, 입주자격 기타) | [15057999](https://www.data.go.kr/data/15057999/openapi.do) | 필수 |
   | 복지로 중앙부처 복지서비스 | [15090532](https://www.data.go.kr/data/15090532/openapi.do) | 필수 |
   | 복지로 지자체 복지서비스 | [15108347](https://www.data.go.kr/data/15108347/openapi.do) | 필수 |
   | LH 분양임대공고별 공급정보 조회 (주택형 목록) | [15056765](https://www.data.go.kr/data/15056765/openapi.do) | 선택 |

3. 신청 화면에서 다음을 채운다.
   - 활용 목적: 웹 사이트 개발. 설명은 1번의 예시를 쓴다.
   - 상세기능: 전부 선택한다.
   - 라이선스 표시에 동의한다.
4. **마이페이지 → 데이터활용 → Open API → 활용신청 현황**에서 승인 상태를 확인한다.
5. 같은 화면에서 일반 인증키를 확인한다. Encoding 키와 Decoding 키가 함께 나온다. `.env`에는 **Decoding 키**를 넣는다. 수집 스크립트는 HTTP 라이브러리가 인코딩하는 것을 전제로 작성한다.

승인 직후에는 키가 바로 동작하지 않을 수 있다. 이때 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 나오면 한두 시간 뒤 다시 시도한다(일반적으로 알려진 동작, 이 프로젝트에서는 미확인).

공공데이터포털에는 "청년"으로 검색되는 API가 이 밖에도 많다. 위 표에 없는 API를 더하는 것은 묶을 API(Q1)를 바꾸는 일이라 지금은 신청하지 않는다. W4 겹침 분석 뒤에 다시 본다.

## 3. 키를 `.env`에 넣는다

1. 저장소 루트에서 `.env.example`을 복사한다.
   ```bash
   cp .env.example .env
   ```
2. `YOUTHCENTER_API_KEY`에 온통청년 키를, `DATA_GO_KR_SERVICE_KEY`에 공공데이터포털 Decoding 키를 넣는다.
3. 키는 커밋하지 않는다. 팀에는 저장소 밖으로 공유한다. 채팅 AI에 키나 `.env` 내용을 붙여넣지 않는다.

## 4. 키가 동작하는지 확인한다

저장소 루트에서 실행한다. 서비스마다 한 번씩, 모두 6번 호출한다(복지로 중앙부처는 하루 한도 100 중 1). 키와 요청 URL은 출력하지 않는다.

```bash
python3 experiments/api-survey/check_keys.py
```

Windows PowerShell에서는 `py experiments/api-survey/check_keys.py`로 실행한다. `python3`를 입력했을 때 "Python"만 출력되고 끝나면, Python이 설치되지 않아 Microsoft Store 바로가기가 실행된 것이다. `winget install Python.Python.3.12`로 설치하고 PowerShell 창을 새로 연다.

모두 `[OK]`이면 끝이다. 키를 하나만 넣었으면 다른 쪽은 `[SKIP]`으로 건너뛴다. `[FAIL]` 줄은 그대로 공유해도 된다. 키가 들어 있지 않다.

## 누구 계정으로 받나

- 수집(T7)은 D1에 따라 한 사람이 한 번 실행한다. 수집용 키는 그 사람 계정 하나로 충분하다.
- 한도는 서비스(활용신청)마다 따로 정해진다. 복지로 중앙부처는 개발계정 기준 하루 100이다.
- 개발계정 한도가 모자라면 운영계정으로 바꿔 한도를 늘릴 수 있다. LH 페이지에는 "활용사례 등록 시 신청하면 트래픽 증가 가능"이라고 적혀 있다. 복지로도 같은 제도라고 추정한다.

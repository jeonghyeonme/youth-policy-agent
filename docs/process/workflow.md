# 작업 규칙

> [문서 지도](../README.md) · 인원·역할이 정해지면(Q5) 이 문서를 고친다. 아래 브랜치·PR 규칙은 **제안**이며 PM이 확정한다.

## 일이 생기고 끝나기까지

1. **PM이 일을 만든다** — STATUS "할 일"에 T 번호로 추가하고, 필요하면 GitHub 이슈도 연다(이슈 제목에 `T4`처럼 번호를 붙인다).
2. **담당자가 맡는다** — STATUS 자기 줄의 상태를 `진행 중`으로 바꾼다.
3. **작업 브랜치에서 한다** — `archive/youth-policy`에서 브랜치를 딴다(D1: 청년 정책 작업은 이 브랜치로 간다. `main`은 생필품 가격 컨셉). 이름은 `t4-context-measurement`처럼 T 번호로 시작한다.
4. **PR을 연다** — `archive/youth-policy` 대상. PR 템플릿을 채운다. **CI가 통과해야 병합한다**([D3](../decisions/D3.md)).
   - 팀원이 없는 지금은 리뷰 없이 PM이 병합한다. PM이 PR 템플릿 "체크"(키·개인정보 없음 등)를 직접 확인한다([D4](../decisions/D4.md)).
   - 팀원이 생기면(T1) 리뷰어 1명 이상 확인 후 병합한다.
5. **마무리 기록** — [마무리 절차](wrap-up.md). PR에 `log/NNN.md`가 함께 들어간다.
6. **PM이 STATUS를 정리한다** — 끝난 줄을 지우고 다음 일을 올린다.

## 막혔을 때

- STATUS 상태를 `막힘(이유)`으로 바꾸고 PM에게 알린다.
- [PM 승인이 필요한 결정](../../AGENTS.md#pm-승인이-필요한-결정)이면 혼자 정하지 않는다 — STATUS "PM 승인 대기"에 Q 번호로 올리고(선택지·추천안 포함), 그 결정에 기대는 부분은 멈춘다. 상태는 `막힘(Q3)`처럼 쓴다.

## AI 코딩 도구를 쓸 때

- 규칙은 [AGENTS.md](../../AGENTS.md)에 있다. 도구가 읽지 못하면 작업 전에 AGENTS.md 내용을 대화에 넣는다.
- AI가 만든 코드·문서도 PR을 거친다. 병합하는 사람(리뷰어가 없으면 PM)이 키·개인정보가 들어가지 않았는지 먼저 본다.
- **채팅 AI(웹)에 API 키나 `.env` 내용을 붙여넣지 않는다.**

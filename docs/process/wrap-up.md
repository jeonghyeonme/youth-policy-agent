# 마무리 절차 — 작업 한 건을 끝낼 때

> [문서 지도](../README.md) · 사람과 AI 도구가 같은 절차를 따른다. AI에게는 "docs/process/wrap-up.md대로 마무리해 줘"라고 하면 된다.

목적: 다음 사람이 `STATUS.md`만 읽고 이어갈 수 있게 한다. **긴 문서를 다시 읽지 않고** 새 파일을 만들고 인덱스에 한 줄만 추가한다.

## 1. 무엇이 바뀌었나

| 바뀐 것 | 기록할 곳 |
| --- | --- |
| 이번 작업의 경위(왜, 근거, 수치, 확인) | `docs/log/NNN.md` 새 파일 — **항상** |
| 내 일의 상태 | `docs/STATUS.md` 내 줄 — **항상** |
| 정한 것 | `docs/decisions/D<번호>.md` 새 파일 + 인덱스 한 줄 |
| 실험 결과 | `experiments/<실험>/results.md` |
| 모두가 지켜야 할 새 규칙 | `AGENTS.md` — 드물다. PM과 상의 |

## 2. 진행 로그 한 건

1. 다음 번호: `docs/log/`에서 가장 큰 번호 + 1. 같은 번호가 PR끼리 겹치면 나중에 병합하는 쪽이 번호를 올린다.
2. `docs/log/NNN.md`:

   ```markdown
   # NNN. <한 일 — 왜를 담은 제목> (YYYY-MM-DD)

   > [진행 로그 인덱스](README.md) · 작성: 이름 · 관련: T번호, PR #n

   **계기**: …
   **한 일**: …
   **근거**: D 번호, 회의 날짜, 수치(실측/계산/가정 표시)
   **확인**: 돌려 본 것과 결과. 확인하지 못했으면 "확인하지 않음"이라고 쓴다
   ```
3. `docs/log/README.md` 표 맨 아래에 한 줄 추가.

## 3. STATUS

- 끝난 일: PM에게 알린다(PM이 줄을 지운다). 혼자 하는 프로젝트처럼 직접 지워도 되면 지우고 PR에 적는다.
- 새로 생긴 위험·결정할 것: "열린 위험"·"결정 대기"에 추가.
- 머리말 "마지막 갱신"을 오늘 날짜와 새 로그 번호로.

# D3. LLM은 질문당 최대 2회만 부른다: 첫 문장 해석 1회, 결과 설명 1회

> [결정 기록 인덱스](README.md) · 승인: 2026-10-29 PM · 원래 Q9 · [log/007](../log/007.md), [log/008](../log/008.md)

**정할 것**: 무료 LLM API 한도 안에서 LLM을 어디에 쓸지.

**검토한 선택지**:
1. 매 턴 LLM이 대화한다(제안서 원안 해석). 질문당 3~5회.
2. 빠진 조건은 버튼 선택지로 묻고, LLM은 첫 자유 문장 해석 1회와 결과 설명 1회만 부른다. 질문당 최대 2회.
3. 2번에서 결과 설명을 사용자가 정책을 눌렀을 때만, 정책 1건씩 부른다.

**결정**: 2번.

**이유**:
- LLM을 포함해 전부 무료 API 키로 구현한다. 무료 등급은 요청 수와 토큰 한도가 작다.
- 조건을 버튼으로 받으면 그 턴에는 LLM이 필요 없다. 거르기는 서버가 한다(D1).
- 3번은 호출이 더 적지만, 결과를 설명해 준다는 서비스의 핵심이 기본 화면에서 빠진다.

**따라오는 것**:
- LLM 한도를 다 쓰면 LLM 없이 결과 카드(정책명, 대상, 마감일, 링크)만 보여 준다. 서비스가 멈추지 않는다.
- LLM에는 서버가 걸러 낸 상위 몇 건의 제목, 요약, 서술형 자격조건, 지원 내용만 넘긴다([공통 정책 형식](../../experiments/api-survey/schema.md)). 몇 건을 넘길지는 정책 1건당 토큰(W6)을 재서 정한다.
- 개발과 테스트는 저장해 둔 LLM 응답을 쓴다. 팀원이 한 무료 키를 같이 쓰기 때문이다.
- 같은 조건의 설명을 서버에 캐시하는 것은 하지 않는다. 캐시 키가 사용자 선택값이라 AGENTS.md "개인정보" 규칙에 걸린다.
- 업체(Q5)를 고를 때 무료 등급의 한도와 입력 데이터 학습 사용 여부를 함께 본다.

**다시 볼 때**:
- 유료 API를 쓰게 되거나, 무료 한도가 질문당 2회도 감당하지 못할 때.
- 결과 설명의 품질이 낮아 대화형 되묻기가 필요하다고 판단될 때.

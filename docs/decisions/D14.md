# D14. `api/chat` 요청·응답 형식을 초안대로 고정한다

> [결정 기록 인덱스](README.md) · 승인: 2026-11-15 PM · 원래 Q9

**정할 것**: 화면(T9)이 기대는 `POST /api/chat`의 요청·응답 형식. 다른 사람 코드가 기대는 형식이라 PM 승인 대상(AGENTS.md "구조").

**검토한 선택지**: T8에서 만든 초안([web/lib/chat/types.ts](../../web/lib/chat/types.ts), log/027) 그대로 / 고쳐서

**결정**: 초안대로 고정한다.
- **요청**: `question`(1~300자) + `profile`.
  - `profile`: `age`(15~49), `sggCode`(시군구 5자리), `job`(0013xxx), 선택: `school`(0049xxx), `marital`(0055xxx), `special`(0014xxx 목록), `incomeBand`(본인 연 소득 6단계: 2천만 원 미만, 2천~3천만 원, 3천~4천만 원, 4천~5천만 원, 5천만 원 이상, 모름), `housing`(무주택·주택 있음·모름), `householdSize`(1~6).
- **응답**: `query`(LLM이 고른 대분류·중분류·키워드·단어), `matched`(필터 통과 건수), `cards`(id, 이름, 운영기관, 지원 내용 앞부분, 판정, 이유, 확인 질문, 신청 종료일, 링크), `more`(카드로 보여 주지 않은 수).
- **오류**: `{ error }`와 상태 코드 400(요청 형식), 500(서버 설정), 502(외부 API 실패), 503(Groq 한도).

**이유**: D10의 선택지 값(소득 구간·주택 여부·학력·가구원 수)을 그대로 담고, D9·D10의 결과(상위 카드, 판정, 근거, 확인 질문, 나머지 수)를 화면이 그대로 그릴 수 있다. 자유 입력은 질문 한 문장뿐이다.

**바꿀 때**: 필드를 더하거나 빼거나 뜻을 바꾸면 새 결정으로 PM 승인을 받는다. 화면과 서버를 같은 PR에서 함께 고친다.

**다시 볼 때**: 화면(T9)을 만들다 빠진 정보가 나올 때. 대화가 여러 턴이 되어 이전 답을 이어받아야 할 때.

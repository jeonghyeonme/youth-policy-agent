# D15. GitHub Actions CI 자동 실행을 끄고, 같은 검사를 로컬에서 돌려 PR에 적는다

> [결정 기록 인덱스](README.md) · 승인: 2026-11-16 PM · 원래 Q 번호 없음(PM 지시) · D3의 "PR마다 실행"과 D4의 "CI 통과 후 병합"을 대체한다

**정할 것**: CI가 계정 결제 문제로 실행되지 않을 때 어떻게 할지. jeonghyeonme/youth-policy-agent#6에서 `check`·`web` 모두 실행 서버가 배정되지 않았다(`runner_id: 0`, 과금 0ms, 재실행도 같음). 해결하려면 과금해야 한다(PM).

**검토한 선택지**:
1. 결제해서 CI를 계속 돌린다
2. 저장소를 공개한다(공개 저장소의 Actions는 무료, T5)
3. CI 자동 실행을 끄고 같은 검사를 로컬에서 돌린다

**결정**: 3. PM이 과금하지 않기로 했다.
- `.github/workflows/ci.yml`은 지우지 않고 자동 트리거만 끈다(`workflow_dispatch`만 남김). 되살릴 트리거를 파일에 주석으로 적어 뒀다.
- 같은 검사를 `.github/scripts/check_all.py`로 한 번에 돌린다: 측정·수집 스크립트 테스트, 문서 링크 검사, web 린트·타입 검사·테스트·빌드.
- PR을 올리는 사람(사람이든 AI든)이 이 스크립트를 돌리고 결과를 PR 설명 "확인"에 적는다. PM은 그걸 보고 병합한다(D4의 리뷰 없는 병합은 그대로).

**잃는 것**: 깨끗한 환경에서 검사한다는 보장. 로컬에 남은 빌드 결과 때문에 CI라면 잡혔을 문제를 놓칠 수 있다(T7에서 `LayoutProps` 오류가 그랬다). 그래서 타입 검사는 `next typegen`부터 돌리게 해 두었다.

**다시 볼 때**: 저장소를 공개할 때(T5) 또는 결제를 해결할 때. 트리거를 되살리고 D3·D4로 돌아간다.

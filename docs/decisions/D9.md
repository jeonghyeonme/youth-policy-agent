# D9. LLM에 넘길 정책은 3단계(요청 좁히기 → 서버 필터 → 상위 8건)로 고른다

> [결정 기록 인덱스](README.md) · 승인: 2026-11-08 PM · 원래 Q3

**정할 것**: 결과를 가장 크게 좌우하는 것(핵심 변수). 측정해 보니 "걸러진 정책 중 무엇을 LLM에 넘기느냐"였다. 대표 질문 A는 지역·나이·취업으로 걸러도 약 250건이 남는데, 한 번에 넘길 수 있는 건 15건 안팎이다(분당 8,000토큰 가정).

**검토한 선택지**: [Q3 실험](../../experiments/context-measurement/q3-ranking.md)
1. 순위 하나로 고른다: API 순서, 조회수, 마감 임박, 지역 전용, 키워드 일치, 조합
2. 3단계: 요청 좁히기 → 서버 필터 → 순위 상위 N건
3. LLM이 직접 고른다: 이름·한 줄 요약을 먼저 보내 고르게 하고, 고른 것의 내용을 다시 보낸다(LLM 호출 두 번)

**결정**: 2.
1. **요청 좁히기**: LLM이 질문에서 정책 키워드(`plcyKywdNm`, 코드정의서 17개)와 중분류(`mclsfNm`)를 고르고, 서버가 그 값과 지역(`zipCd`)·대분류(`lclsfNm`)로 온통청년 API를 부른다.
2. **서버 필터**: 나이(최소·최대 나이 숫자로. `sprtTrgtAgeLmtYn`은 쓰지 않는다), 취업 요건, 신청 가능(마감 제외).
3. **순위**: 키워드 일치 → 지역 전용(구 > 시도 > 전국) → 마감 임박 순으로 **상위 8건**(약 2,300토큰)만 LLM에 넘긴다. 나머지는 "N건 더 있음"으로 알린다.

**이유**:
- 질문 A에서 297 → 73(키워드 보조금) → 11 → 8건. API 한 번 호출로 끝났다(실측).
- 순위 기준 중 키워드 일치가 질문에 맞는 정책을 가장 잘 올렸다. 조회수는 서울 정책을 하나도 못 올렸다.
- 3번(LLM이 직접 고르기)은 답변 한 번에 LLM 호출이 두 번이라 무료 한도를 두 배로 쓴다.

**다시 볼 때**:
- 실제 질문으로 시험해 상위 8건에 사용자가 찾는 정책이 자주 빠질 때: 3번을 시험한다.
- Groq 무료 한도가 넉넉하다고 확인될 때: 넘기는 건수(8)를 늘린다.

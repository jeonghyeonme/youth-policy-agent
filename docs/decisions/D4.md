# D4. 팀원이 생기기 전까지 PR은 리뷰 없이 CI 통과 후 PM이 병합한다

> [결정 기록 인덱스](README.md) · 승인: 2026-11-07 PM · 원래 Q 번호 없음(PM 직접 지시)

**정할 것**: `docs/process/workflow.md`의 "리뷰어 1명 이상 확인 후 병합"을 지금 지킬 수 있나

**검토한 선택지**:
1. 그대로 둔다. 팀원이 없어 병합할 수 없거나, 규칙을 어기고 병합하게 된다
2. 팀원이 생기기 전까지 리뷰를 빼고, CI 통과와 PM의 체크 확인으로 대신한다

**결정**: 2. 팀원이 없는 동안은 CI([D3](D3.md))가 통과하면 PM이 리뷰 없이 병합한다. 병합 전에 PM이 PR 템플릿 "체크"(키·`.env`·개인정보 없음, log 추가)를 직접 확인한다. 같은 결정에서 workflow.md의 브랜치·PR 대상을 `main`에서 `archive/youth-policy`로 고쳤다(D1과 맞춤).

**이유**: 지금은 PM 혼자 작업한다. 리뷰어를 기다리면 일이 멈춘다. 리뷰가 하던 기계적인 확인(테스트, 링크)은 CI가 맡는다. 키·개인정보 확인은 사람이 봐야 해서 PM에게 남긴다.

**다시 볼 때**: 팀원이 생길 때(T1). 그때는 리뷰어 1명 이상 규칙으로 돌아간다.

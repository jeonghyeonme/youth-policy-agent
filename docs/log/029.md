# 029. 실제 키로 질문 A가 끝까지 돌았고(M1), 드러난 문제 셋을 고쳤다 (2026-11-15)

> [진행 로그 인덱스](README.md) · 작성: AI(Claude Code) · 관련: T8, D7, D8, D10, log/027

**계기**: PM이 로컬에서 `scripts/try-question.ts A`와 `B`를 실행해 결과를 붙여 줬다.

**결과 (실측)**:
- **질문 A: 6.2초에 카드 8장. M1 확인.**
  - 이해 단계: 입력 458 + 출력 655토큰. 출력 중 추론이 617토큰이다.
  - 판정 단계: 입력 3,425 + 출력 1,471토큰. 출력 중 추론이 1,015토큰이다.
  - 합계 약 6,000토큰.
  - LLM은 중분류 "취업"과 키워드 "보조금"을 골랐다. 8건이 남아 모두 카드가 됐다(나머지 0).
- **질문 B: 판정 단계에서 Groq 429(재시도까지 13초).** A 바로 뒤에 돌려 1분 안에 약 8,000토큰을 넘은 것으로 보인다. 무료 한도가 분당 8,000토큰이라는 실측 근거다(콘솔 값은 아직 확인 전).
- **질문 A 판정 8건**
  - 맞음 5건: 국가기술자격 응시료(가능), 취업날개(가능), 군장병(불가), 문화예술 연수단원(확인 필요, 질문 알맞음), 게임사 현장교육(확인 필요, 질문 알맞음).
  - 청년일자리도약장려금: "불가"(기업이 신청). Q4 정답표의 "확인 필요"와 다르지만 원문상 사업주가 신청하므로 받아들일 만하다.
  - 돌봄보조 인력: 판정은 "확인 필요"(서버가 특화 요건으로 바꿈). 그런데 이유는 LLM의 "연령 조건에 부합"이고 확인 질문은 비어 있어 앞뒤가 맞지 않았다.
  - 무대기술인턴십: "불가"로 잘못 판정했다. 근거로 든 "자격증 3급 이상 또는 경력 3년"은 공연단체 소속 직원의 요건이다. 인턴 채용 조건은 "만 39세 이하 입직 희망자, 별다른 자격 없음"이다.

**고친 것**:
- `codeVerdict.ts`: `codeCheck`가 판정과 함께 이유·확인 질문을 낸다(예: "여성, 기초생활수급자, … 중 해당하는 것이 있나요?"). `merge`는 서버가 판정을 바꾼 경우 서버의 이유·질문을 쓴다.
- `judge.ts`: 프롬프트에 "운영 단체·기업·고용주의 요건과 신청하는 청년의 요건을 구분해, 청년의 요건으로만 판정한다"를 넣었다.
- `groq.ts`, `understand.ts`: `reasoning_effort` 옵션을 추가했다. 이해 단계는 `low`로 부른다. 판정 단계는 품질을 쟀던 기본값을 그대로 둔다.
- `scripts/try-question.ts`: 429면 안내된 시간만큼 기다렸다가 한 번 다시 부른다. 서버(`api/chat`)는 지금처럼 503을 돌려준다.
- 테스트 4개를 추가해 모두 27개다.

**근거**:
- `reasoning_effort`(low·medium·high)는 Groq 문서(console.groq.com/docs/reasoning)에 gpt-oss 20B·120B 지원으로 적혀 있다. 추론 토큰이 분당 한도에 들어가는지는 문서에 없다.
- 판정 단계 추론 강도는 낮추지 않았다. Q4 품질(8/14)을 기본값으로 쟀다. 낮춰서 품질이 유지되는지는 다시 재야 한다.
- 서버의 재시도는 넣지 않았다. 13초를 기다리면 화면 응답이 너무 느려지고, 무료 플랜 함수 실행 시간 제한도 확인하지 않았다.

**확인**:
- 로컬에서 테스트 27개, 타입 검사, 린트가 통과했다.
- 고친 프롬프트와 `low` 추론으로 실제 실행은 다시 하지 않았다(PM 로컬 실행 필요). 무대기술인턴십 판정이 바뀌는지, 이해 단계 토큰이 줄어드는지는 그때 확인한다.

# 005. 응답 샘플 수집 스크립트를 만들었다 (2026-10-29)

> [진행 로그 인덱스](README.md) · 작성: Claude Code (PM 요청) · 관련: T7, D1

**계기**: 공공데이터포털 키 확인이 통과해 W2(응답 샘플 수집)를 시작했다. 온통청년 키는 심사 대기 중이다.

**한 일**:
- `experiments/api-survey/collect_samples.py`를 만들었다. 키가 있는 출처만 수집한다.
- 출처별 호출 수(첫 실행): 잡알리오 7, LH 최대 8, 복지로 중앙부처 21, 복지로 지자체 12, 온통청년 약 40.
- 응답은 `samples/<출처>/<기능>-<페이지 또는 ID>.json`에 원본 그대로 저장한다. 요청값, HTTP 상태, 받은 시각도 같이 남기고, 키와 요청 URL은 남기지 않는다.
- api-survey README에 실행 방법과 호출 수를 적고, STATUS T7을 "진행 중"으로 바꿨다.

**근거**:
- 이미 받은 파일(HTTP 200)은 다시 호출하지 않는다. 다시 실행해도 복지로 중앙부처 한도를 다시 쓰지 않고, 실패한 요청만 다시 시도한다. D1의 수집기로 키울 때도 같은 성질이 필요하다.
- 상세는 생애주기에 "청년"이 들어간 서비스를 먼저 고른다. LH는 임대 공고를 먼저 고른다. 서비스 대상(사회 초년생)에 맞는 샘플을 먼저 보기 위해서다.
- 응답 형식(JSON·XML)과 목록이 들어 있는 위치를 아직 모른다. 그래서 XML도 dict로 바꾼 뒤, ID 필드(`recrutPblntSn`, `PAN_ID`, `servId`, `plcyNo`)를 가진 항목을 응답 전체에서 찾는다. 온통청년의 `plcyNo`와 `totCount`는 추정한 필드 이름이다.
- 응답 파일을 커밋해 팀과 공유한다. 공개 데이터이고 키가 들어 있지 않다.

**확인**:
- 가짜 응답으로 돌렸다.
  - 출처별 호출 수가 위 표대로 나왔다.
  - 복지로 중앙부처 상세 20건은 모두 청년 포함 서비스였고, LH 상세 5건은 모두 임대 공고였다.
  - 다시 실행하자 추가 호출이 0회였다. 저장 파일에 키 문자열, `serviceKey`, `apiKeyNm`이 없었다.
  - 모든 요청이 인증 오류일 때는 목록 6회만 호출하고 상세는 부르지 않았다. 다시 실행하면 그 6회만 다시 시도했다.
- 실제 키로는 돌리지 않았다. PM 실행 결과를 기다린다.

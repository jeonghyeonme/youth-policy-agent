# 027. 질문 한 턴(POST /api/chat)을 만들고 개인정보 규칙을 테스트로 고정했다 (2026-11-13)

> [진행 로그 인덱스](README.md) · 작성: AI(Claude Code), PM 지시 · 관련: T8, D5, D7, D9, D10, Q9

**계기**: PM이 2주째 작업(T8)을 진행하라고 했다. 목표는 M1, 질문 A를 보내면 판정 카드 데이터가 오는 것이다.

**한 일** (`web/`):
- `lib/llm/understand.ts`: 질문에서 대분류·중분류·정책 키워드를 고른다(D9 1단계). 순위에 쓸 단어도 고른다. 고른 값은 코드정의서 목록(`vocab.ts`)으로 다시 검증하고, 목록 밖이면 버린다.
- `lib/llm/judge.ts`: 서술형 자격 판정 프롬프트(D10 2단계). 실험 프롬프트에 log/019의 개선 두 가지를 넣었다.
  - "불가"는 기업·기관 대상이거나 원문이 분명히 배제할 때만 쓴다.
  - 2026년 기준 중위소득 표를 함께 준다.
- `lib/llm/groq.ts`: Groq 호출(fetch, JSON 모드, `openai/gpt-oss-120b`)과 429 한도 오류.
- `lib/chat/answer.ts`: 질문 한 턴을 처리한다.
  1. 질문 이해(LLM)
  2. 온통청년 호출. 키워드로 좁혀 0건이면 대분류만으로 한 번 더 부른다.
  3. 필터와 순위로 상위 8건. 판정 프롬프트가 토큰 예산(입력 4,500)을 넘으면 건수를 줄인다.
  4. 코드 판정과 서술형 판정(LLM)
  5. 카드로 만든다.
- `lib/chat/types.ts`, `validate.ts`: 요청·응답 형식(초안)과 요청 검증.
- `app/api/chat/route.ts`: `POST /api/chat`. 오류 응답은 이렇다.
  - 키가 없으면 500
  - 요청이 잘못되면 400
  - Groq 한도에 걸리면 503
  - 나머지는 502
- `lib/policy/medianIncome.ts`: 2026년 기준 중위소득 1~6인(월). 출처는 아래 근거에 있다.
- `scripts/try-question.ts`: 사람이 실제 키로 대표 질문 A·B를 돌려 보는 스크립트.
- 테스트 13개를 추가해 모두 23개다.
  - 질문 A 한 턴: 11건 중 8건 카드, 나머지 3건
  - 서버 코드 판정이 LLM의 "가능"보다 앞선다
  - 개인정보: 공공 API 요청에 질문 문장이나 목록 밖 값이 들어가지 않는다
  - 0건일 때 다시 부르기, 판정 생략, 토큰 예산으로 건수 줄이기
  - 판정·이해 결과 검증, 요청 검증, Groq 요청 형식과 429

**근거**:
- **api/chat 형식**: 화면(T9) 코드가 기대는 형식이라 PM 승인 대상이다(AGENTS.md "구조"). 초안으로 만들고 STATUS Q9에 올렸다. 승인 전에는 이 PR을 병합하지 않는 것이 맞다.
- **중위소득 출처**: 복지로 "2026년도 '기준 중위소득' 역대 최대 인상"(2025-08-08, 정보제공 보건복지부)이다. 1인 월 2,564,238원, 4인 월 6,494,738원.
  - 웹 검색에서는 1인 가구 금액이 출처마다 달랐다. 그래서 복지로 원문에서 확인했다.
- **소득 구간**: 본인 연 소득 6단계(2천만 원 미만 ~ 5천만 원 이상, 모름)로 정했다. D10의 "소득 구간을 선택지로"를 구체화한 것이라 Q9에 같이 올렸다.
- **LLM에 보내는 값**: D10의 범위인 나이, 취업, 학력, 혼인, 소득 구간, 주택, 가구원 수다. 시군구 코드는 판정에 필요 없어 LLM에 보내지 않는다(테스트로 확인).
- **Groq SDK를 쓰지 않은 이유**: fetch 한 번이면 되고 의존성을 늘리지 않는다. 실험(judge_experiment.py)과 같은 요청 형식이다.
- **토큰 예산**: 한국어 1글자를 0.7토큰으로 넉넉히 센다. 실측 o200k 값은 0.46~0.66이다(log/012). 판정 입력 상한은 분당 8,000토큰 가정에서 4,500으로 잡았다.
- **Next 16 Route Handler**: `node_modules/next/dist/docs/`의 안내를 읽고 만들었다(D13). POST는 캐시되지 않는다.

**확인**:
- 로컬에서 린트, 타입 검사(`.next`를 지운 깨끗한 상태), 테스트 23개, 빌드가 통과했다.
- 개인정보 테스트가 실제로 잡는지 확인했다. 질문 문장을 일부러 API 요청에 넣자 실패했고, 되돌리니 통과했다.
- `next start`로 서버를 띄워 확인했다. 키가 없으면 500, 시군구 코드가 틀리면 400, 본문이 JSON이 아니면 400, GET이면 405가 나왔다. 서버 로그에 요청 내용은 남지 않았다.
- **실제 온통청년·Groq로 한 턴을 돌리지는 않았다**(AI는 키를 쓰지 않는다). PM이 `node --env-file=../.env scripts/try-question.ts A`로 확인한다.

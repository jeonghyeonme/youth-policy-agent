# 008. 법률 정보안 v4: API 하나·LLM 2회 구조로 토큰을 다시 재는 스크립트를 만들었다 (2026-11-01)

> [진행 로그 인덱스](README.md) · 작성: Claude Code (PM 요청) · 관련: Q7, T6

**계기**: v3에서 법률 정보안이 하루 약 17개로 조건(30개)에 못 미쳤다. PM이 API·데이터·LLM 호출을 줄여 다시 재기로 하고, 범위를 노동·주거 + `law` API 하나로 정했다(선택지 1).

**한 일**:
- `experiments/legal-tokens/two_call.py`: 법령 4개 전체 본문을 한 번 받아 `laws/`에 조문 단위로 저장하고, LLM 1회차(목차에서 조문 선택, JSON)와 2회차(고른 조문만으로 답)로 질문당 토큰을 잰다. 답에 넘겨주지 않은 조문 번호가 있는지 검사한다.
- README에 v4 절을 넣고 STATUS T6 상태를 바꿨다.

**근거**:
- v3 도구 호출 21회 중 목록 검색이 15회였고, 품질 오류는 모두 조문 번호를 짐작해서 생겼다(실측). 그래서 검색을 없애고 목차를 주는 쪽을 택했다.
- 작업 안에서 정한 것: 법령은 근로기준법·최저임금법·주택임대차보호법·민법(임대차 제618~654조). 조문은 최대 3개, 조문 하나는 1,500자까지. 개정 표시(`<개정 …>`)는 빼서 토큰을 줄였다. 사례는 노동 4, 주거 3.
- `--toc domain`은 분야 버튼 UI를 가정한 비교용이다. UI 형태는 정하지 않았다.

**확인**:
- `--fake`로 수집(법령마다 2회), 목차·조문 파싱(항·호, 가지번호 제6조의3, 장 제목 제외, 개정 표시 제거), 두 호출, 목차에 없는 조문 표시, 넘겨주지 않은 조문 인용 검출, `--toc domain`을 확인했다. 저장 파일에 가짜 OC 값 없음.
- 실제 응답의 조문 구조는 저장된 근로기준법 제55조 응답 하나로만 확인했다. 전체 본문 응답, 호·목이 있는 조문, Groq 엄격 JSON 출력은 실제로 확인하지 않음.

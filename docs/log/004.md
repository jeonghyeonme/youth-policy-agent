# 004. 문서 링크가 깨지지 않게 CI를 붙였다 (2026-11-07)

> [진행 로그 인덱스](README.md) · 작성: AI(Claude Code), PM 지시 · 관련: D3, PR jeonghyeonme/youth-policy-agent#1

**계기**: PM이 CI를 설정하자고 했다.

**한 일**:
- `.github/workflows/ci.yml`: 모든 PR과 `archive/youth-policy` 푸시에서 Python 3.12로 두 가지를 돌린다. 측정 스크립트 단위 테스트, 문서 링크 검사.
- `.github/scripts/check_links.py`: 저장소의 모든 `.md`에서 상대 링크를 찾아, 가리키는 파일이 있는지 확인한다.
- `docs/decisions/D3.md`와 인덱스 한 줄.

**근거**:
- 링크 검사는 경로만 본다. `#앵커`는 확인하지 않는다. 한글 제목의 앵커 규칙을 GitHub와 똑같이 맞추려면 코드가 커지는데, 지금은 파일 이동·삭제로 깨지는 경로를 잡는 것이 목적이다.
- 외부 URL은 검사하지 않는다. 공공 사이트가 CI 러너의 요청을 막거나 느리면 PR이 이유 없이 실패한다.
- 링크 검사 스크립트를 `.github/scripts/`에 뒀다. 새 최상위 디렉토리를 만들면 PM 승인 대상이라서(AGENTS.md "구조").
- `main`에는 이 워크플로가 없다. `main`을 대상으로 하는 PR에서는 CI가 돌지 않는다.

**확인**:
- 로컬에서 두 검사를 돌렸다. 테스트 5개 통과, 링크 검사 통과(종료 코드 0).
- 링크 검사가 실패도 잡는지 확인했다. 깨진 링크가 든 임시 `.md`를 넣으면 종료 코드 1과 파일·링크를 출력했다. 확인 뒤 지웠다.
- 워크플로 YAML은 파서로 문법만 확인했다. GitHub에서 실제로 도는지는 이 PR의 체크 결과로 본다.

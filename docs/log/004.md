# 004. 법률 정보안의 질문당 토큰을 재는 스크립트를 만들었다 (2026-10-31)

> [진행 로그 인덱스](README.md) · 작성: Claude Code (PM 요청) · 관련: Q7, T6

**계기**: Q7 추천안의 확정 조건(무료 LLM으로 하루 30개 질문 이상)을 실측으로 확인하기 위해.

**한 일**:
- `experiments/legal-tokens/trial.py`: LLM이 `search_law`·`get_law` 도구로 국가법령정보 API를 부르는 루프를 돌리고, Groq `usage`를 더해 질문당 토큰과 하루 질문 수를 낸다. `--fake`로 키 없이 흐름을 확인할 수 있다.
- `experiments/legal-tokens/README.md`: 준비, 실행, 한도, 읽는 법.
- `.env.example`: `GROQ_API_KEY`, `LAW_API_OC` 이름을 추가했다.

**근거**:
- Groq 모델 설정·429 재시도·`.env` 읽기는 청년 정책 브랜치 `experiments/llm-providers/trial.py`·`experiments/api-survey/check_keys.py`를 따랐다. 같은 업체·같은 한도(하루 200K 토큰)로 비교해야 3안 비교의 청년 정책 실측(질문당 2.5K~3.4K)과 맞는다.
- `experiments/` 폴더는 wrap-up.md의 `experiments/<실험>/` 규칙과 청년 정책 브랜치 관례를 따랐다.
- 작업 안에서 정한 것: 도구는 두 개로 줄였다(제안서는 10종). 토큰을 좌우하는 것은 도구 수보다 호출 횟수와 넘기는 본문 길이라고 보고, 이 둘을 `--max-steps`, `--max-chars`로 바꿔 볼 수 있게 했다. 사례는 제안서 7.1에서 6개를 골랐다.
- 법령 API 응답 링크에 OC 값이 들어가므로 저장과 LLM 전달 전에 지운다(AGENTS.md "API 키").

**확인**:
- `--fake`로 두 모델 × 6사례를 돌려 루프, 결과 저장, 요약, 같은 요청 재사용(법령 API 실제 호출 2회), 본문 자르기(5,000자 → 3,015자), 단계 상한 시 `forced` 표시를 확인했다. 저장된 파일 어디에도 가짜 OC 값이 남지 않았다.
- 실제 Groq와 국가법령정보 API로는 돌리지 않았다. 응답 키 이름(`법령ID` 등), 조문 지정(`JO`) 동작, Groq 도구 호출 형식은 확인하지 않음.

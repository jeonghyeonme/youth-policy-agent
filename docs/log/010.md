# 010. Groq 키 발급 절차와 키 확인을 추가했다 (2026-10-29)

> [진행 로그 인덱스](README.md) · 작성: Claude Code (PM 요청) · 관련: Q5

**계기**: PM이 Q5 주 업체 후보인 Groq의 키 발급부터 돕기를 요청했다.

**한 일**:
- `api-keys.md`에 Groq 가입, 키 생성, 데이터 보관 설정 확인 절차를 추가했다.
- `.env.example`의 `LLM_API_KEY`를 `GROQ_API_KEY`와 `MISTRAL_API_KEY`로 나눴다. `LLM_API_KEY`를 쓰는 코드는 없었다.
- `check_keys.py`에 Groq 검사를 넣었다. `GET https://api.groq.com/openai/v1/models`로 모델 목록만 조회한다.

**근거**:
- 환경변수 이름 `GROQ_API_KEY`는 Groq 공식 빠른 시작 문서가 권장하는 이름이다.
- 키 검사에 채팅 호출 대신 모델 목록 조회를 쓴 것은 하루 200K 토큰 한도를 쓰지 않기 위해서다.
- 무보관(ZDR)을 사용자가 직접 켤 수 있는지는 자료가 엇갈린다. 공식 문서는 Data Controls 설정을 가리키고, 제3자 한 곳은 기업 계약에서만 된다고 했다. 그래서 문서에는 "화면에서 직접 확인"으로 적었다.

**확인**: 가짜 응답으로 Groq 검사를 돌렸다. 정상 응답에서 `[OK]`와 비교 후보 모델이 나왔고, 401 응답에서 `[FAIL]`이 나왔다. 출력에 키가 없었다. 기존 검사(공공데이터포털, 수집 스크립트)도 다시 통과했다. 실제 키로는 돌리지 않았다.

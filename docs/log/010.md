# 010. v5: 주제→조문 표와 절차 한계 규칙을 넣은 측정을 만들었다 (2026-11-01)

> [진행 로그 인덱스](README.md) · 작성: Claude Code (PM 요청) · 관련: Q7, T6

**계기**: v4에서 7건 중 3건이 핵심 조문을 고르지 못했고, 그때 번호 없이 기억으로 기준·절차를 채웠다. PM이 주제→조문 표를 넣어 다시 재기로 했다.

**한 일**:
- `experiments/legal-tokens/topics.json`: 노동 13개, 주거 11개 주제와 근거 조문.
- `two_call.py --topics`(v5): 1회차에 주제 표를 함께 주고, 고른 주제의 조문은 서버가 넣는다(최대 4개). 2회차에 "준 조문 밖의 기준을 기억으로 채우지 않기", "절차는 신고처·서류 대신 공식 안내 확인 필요" 규칙을 더했다. 사례 c11~c15를 더했다.
- 결과 폴더를 `results-v4/`에서 `results-two-call/`로 바꿨다(v4·v5 함께).

**근거**:
- 주제와 조문은 작업 안에서 정했다. 조문 번호는 `laws/` 원문의 제목·본문으로 확인했다(예: 근로기준법 제18조③ 15시간 미만 제외, 제36조 14일 이내 금품 청산, 주택임대차보호법 제3조④ 양수인 승계, 제7조② 증액 20분의 1 상한). 어느 주제에 어느 조문이 맞는지는 법률 전문가 검토를 거치지 않았다.
- 주제 표에 기존 7개 사례의 답이 들어 있어 그 사례들의 개선은 낙관적이다. 그래서 표를 만든 뒤 c11~c15를 썼다.
- 주제 표 1,918자가 1회차에 더해진다(실제 laws/ 기준). 토큰은 v4보다 늘 것이다(추정).

**확인**:
- 실제 `laws/`로 주제 표 24개의 조문 49개가 모두 있는지 확인했다.
- `--fake`로 주제 선택 → 조문 확장, 없는 주제 무시, 중복 조문 제거, v4 모드 그대로 동작을 확인했다. 실제 Groq로는 돌리지 않았다.

# 025. web/ 골격을 만들고 정책 로직을 옮겨 실험과 같은 숫자를 테스트로 고정했다 (2026-11-13)

> [진행 로그 인덱스](README.md) · 작성: AI(Claude Code), PM 지시 · 관련: T7, D8~D12, log/017

**계기**: PM이 1주째 작업(T7)을 진행하라고 했다.

**한 일**:
- `web/`: `create-next-app@16.4.3`로 Next.js(TypeScript, App Router, Tailwind, ESLint) 골격을 만들었다. 기본 첫 화면·이미지·README는 프로젝트 것으로 바꿨다.
- `web/lib/policy/`: `types.ts`(정책·사용자 조건 타입), `filter.ts`(D9 2단계), `rank.ts`(D9 3단계), `codeVerdict.ts`(D10 1단계와 LLM 판정 합치기).
- `web/lib/sources/`: `youthcenter.ts`(요청 URL, 응답 해석, 첫 페이지 가져오기), `cache.ts`(D8 메모리 캐시).
- 테스트 10개(`npm test`)로 실험 숫자를 고정했다.
  - 질문 A': 73 → 11건, 상위 8건 순서
  - 질문 B: 6건, 1위
  - 고교생 대상 정책 제외
  - Q4 혼합 판정: 8/14, 잘못된 "가능" 0건
  - 캐시, URL, 응답 형식 오류
- CI에 `web` 작업을 추가했다: `npm ci` → 린트 → 타입 검사 → 테스트 → 빌드.
- Python 실험 수정
  - `rank_experiment.py`: 맞춤도 점수를 나이 숫자로 매긴다.
  - `judge_experiment.py`: 정답표의 정책 이름으로 대상을 고른다.

**근거**:
- **버전**: next와 eslint-config-next는 16.4.3이다. 최신 16.4.6은 나온 지 나흘이라, 나온 지 2주 넘은 것 중 가장 새 것을 골랐다.
- **테스트 도구**: Node 22에 들어 있는 `node --test`를 쓴다.
  - vitest는 `npm install` 중 npm 자체 오류로 설치되지 않았다. 오류는 `Cannot read properties of null (reading 'edgesOut')`로, peer 의존성을 계산하다 났다.
  - 내장 도구는 의존성을 늘리지 않고 TypeScript를 바로 실행한다.
  - 그래서 `lib/` 안에서는 `.ts` 확장자를 붙여 불러온다(`tsconfig`의 `allowImportingTsExtensions`). 생성자 매개변수 속성처럼 타입 지우기만으로는 실행되지 않는 문법은 쓰지 않는다.
- **샘플 위치**: 테스트가 `experiments/context-measurement/samples/`를 그대로 읽는다.
  - 계획(log/024)은 `web/test/fixtures/`에 복사하기로 했다. 같은 파일을 두 곳에 두지 않으려고 바꿨다.
  - Vercel 빌드는 테스트를 돌리지 않으므로 영향이 없다.
- **경계에서 해석**: API 응답(문자열)은 `parsePolicy`에서 한 번만 `Policy`로 바꾼다.
  - 나이는 숫자로만 읽고, 0~0이면 `null`(제한 없음)이다.
  - 그 뒤의 코드는 나이 제한 표시값(`sprtTrgtAgeLmtYn`)을 볼 수 없다.
- **순위 맞춤도 수정**: Python 실험은 맞춤도 점수에 아직 나이 제한 표시값을 쓰고 있었다. log/017에서는 필터만 고쳤다.
  - 나이 숫자로 바꾸니 질문 A' 상위 8건에서 사업주 대상 2건이 빠지고, 청년 개인 대상 2건이 들어왔다.
  - 더 맞는 결과라서 TS와 Python을 모두 이렇게 맞췄다.
- **사용자 값을 모를 때**: 학력·혼인을 묻지 않았으면, 코드 판정은 "불가" 대신 "확인 필요"를 낸다. Python 실험은 값을 모두 안다고 가정했다.
- **`web/AGENTS.md`**: Next.js가 `next dev` 때 만드는 AI 도구 안내 파일이다. 저장소에 규칙 파일을 추가하는 것은 PM 승인 대상이라, `web/.gitignore`로 빼고 STATUS Q8에 올렸다.
- **npm audit**: 중간 등급 8건이다. 모두 린트 도구(typescript-eslint)의 개발 의존성이고 서비스 번들에 들어가지 않는다. 그래서 `--force` 업그레이드는 하지 않았다.

**확인**:
- 로컬에서 린트, 타입 검사, 테스트 10개, 빌드가 통과했다. Python 단위 테스트와 링크 검사도 통과했다.
- 테스트가 실제로 잡는지 확인했다. 나이 0~0을 제한 없음으로 보지 않도록 일부러 바꾸자 테스트 3개가 실패했고, 되돌리니 통과했다.
- 온통청년 실제 호출은 하지 않았다. 가짜 fetch로만 시험했다. 실제 호출은 2주째 `api/chat`을 사람이 로컬에서 돌릴 때 확인한다.

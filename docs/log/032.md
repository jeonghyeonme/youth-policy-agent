**계기**: PM이 "main에 생필품 컨셉은 이제 없애고 지금 컨셉으로 main을 덮어씌우자", "이미 Public"이라고 했다.

**한 일**:
- 공개 여부 확인: 인증 없이 GitHub API를 불러 `visibility: public`, 기본 브랜치 `main`을 확인했다.
- 공개 전 점검(같은 날): 브랜치 5개, 커밋 108개 전체에서 `.env` 파일, Groq 키 형태, 공공데이터포털 키 형태, 키 파라미터 뒤 값을 찾았다. 나온 것 없음. 커밋 작성자 이메일에 개인 주소가 있음을 PM에게 알렸다.
- 작업 브랜치에 `git merge -s ours origin/main`: `main`의 생필품 커밋(`afb334b`)을 이력으로 받고 파일 내용은 청년 정책을 유지했다. 그래서 이 브랜치를 `main`에 넣는 PR은 충돌이 없다.
- `main`에만 있던 `docs/decisions/D1.md`를 되살렸다(결정 기록은 지우지 않는다). 인덱스에 D1을 "D16으로 대체"로 올렸다.
- D16(main을 청년 정책으로, D1 대체), D17(CI 다시 켬, D15 대체). D3 상태를 "유효(D15로 잠시 껐다가 D17로 다시 켬)"로 바꿨다.
- `.github/workflows/ci.yml`: 트리거를 모든 PR과 `main` 푸시로 되살렸다(수동 실행도 남김).
- `docs/process/workflow.md`: 브랜치를 `main`에서 따고 `main`으로 PR, CI 통과 후 병합.
- STATUS: 현재 단계 줄, T5(저장소 공개) 줄 삭제. `web/README.md` 검사 절.

**근거**:
- force push 대신 병합을 골랐다. 되돌리기 쉽고 `main` 이력이 남는다.
- `main`에만 있던 진행 로그 002(생필품 전환 기록)는 이 저장소의 log/002와 번호가 겹쳐 파일로 되살리지 않았다. 커밋 `afb334b`에 남아 있다.
- 결정 파일은 고치지 않는 규칙이라 D1·D3·D4·D15 본문은 그대로 두고, 바뀐 것은 인덱스와 새 결정에 적었다.
- 이 PR(jeonghyeonme/youth-policy-agent#6)의 대상을 `archive/youth-policy`에서 `main`으로 바꾼다. T8과 `main` 전환이 한 PR로 들어간다.

**확인**:
- 로컬: `python3 .github/scripts/check_all.py` 6단계 통과(아래 커밋 뒤).
- `git diff origin/main`이 청년 정책 내용 전체를 보여 주고, `git merge-base`로 `main`이 이 브랜치의 조상임을 확인한다(PR이 충돌 없이 들어간다).
- 공개 저장소에서 CI가 실제로 도는지는 PR에서 확인한다.

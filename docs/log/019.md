# 019. Groq 판정을 정답표와 비교해 Q4 추천안(서버 코드 + LLM 서술형)을 올렸다 (2026-11-08)

> [진행 로그 인덱스](README.md) · 작성: AI(Claude Code), PM 요청 · 관련: Q4, D7, D9

**계기**: PM이 Q4 추천안을 요청했다. LLM이 서술형 조건을 실제로 얼마나 맞게 판단하는지 재야 했다.

**한 일**:
- `q4/labels.json`: D9로 고른 정책 14건(A 8, B 6)의 정답표. **LLM 결과를 보기 전에** AI가 원문을 읽고 정했다. 가상 인물 2명.
- `judge_experiment.py`: `--run`은 사람이 로컬에서 Groq를 부른다(2회). 기본 실행은 저장된 결과를 채점한다. 서버 코드 판정(학력·혼인·취업·특화)을 더한 혼합 방식도 함께 채점한다.
- PM이 로컬에서 실행해 결과를 push했다. 응답에 키가 없는지 확인했다(없음).
- `q4-judgement.md`에 결과와 추천안, STATUS Q4 줄 갱신.

**근거**:
- 정답표는 한 사람(AI)이 정했다. 특히 "확인 필요"와 "불가"의 경계(게임사 현장교육, 일자리도약장려금)는 판단이 갈릴 수 있다.
- 위험 지표는 "정답이 가능이 아닌데 LLM이 가능이라 한 건수"로 정했다. 사용자를 잘못 안내하는 오류가 가장 나쁘다고 봤다.
- 개인정보: 실험은 가상 인물의 연봉·주택 여부 등을 LLM에 보냈다. 실제 서비스에서 보낼 값은 Q4와 함께 PM이 정한다.

**확인**:
- 실측: LLM 단독 6/14(위험 2), 혼합 8/14(위험 0). 표본이 14건이라 비율보다 오류 유형을 보는 데 쓴다.
- 혼합은 같은 LLM 결과에 서버 판정을 덮어 계산했다. 프롬프트 개선("불가" 줄이기, 중위소득 표)은 시험하지 않음.

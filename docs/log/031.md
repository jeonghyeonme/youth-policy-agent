# 031. 결제 없이 진행하려고 CI 자동 실행을 끄고 로컬 검사 스크립트로 바꿨다 (2026-11-16)

> [진행 로그 인덱스](README.md) · 작성: AI(Claude Code), PM 지시 · 관련: D15, D3, D4, jeonghyeonme/youth-policy-agent#6

**계기**: jeonghyeonme/youth-policy-agent#6의 CI가 실행 서버를 받지 못하고 2초 만에 실패했다. 재실행도 같았다(`runner_id: 0`, 과금 0ms). 지난번 결제 문제(log/004 이후 PR #1) 때와 같은 증상이다. PM이 "해결하려면 과금해야 되는 상황"이라며 CI는 돌리지 말고 진행하자고 했다.

**한 일**:
- `.github/scripts/check_all.py`: CI가 하던 검사 6가지를 로컬에서 차례로 돌린다. 측정·수집 테스트, 링크, web 린트·타입 검사·테스트·빌드. Windows(`py`)에서도 돌도록 Python으로 썼다. 처음 실패에서 멈추고 통과·실패·건너뜀을 요약한다.
- `.github/workflows/ci.yml`: 자동 트리거를 끄고 `workflow_dispatch`만 남겼다. 되살릴 트리거는 주석으로 남겼다.
- `docs/decisions/D15.md`와 인덱스. D3 상태를 "자동 실행은 D15로 대체"로 바꿨다(결정 파일 자체는 고치지 않음).
- `docs/process/workflow.md`: 병합 조건을 "CI 통과"에서 "로컬 검사 통과, 결과를 PR 설명에 적기"로 바꿨다. STATUS 현재 단계 줄과 `web/README.md` 검사 절도 맞췄다.

**근거**:
- 워크플로 파일을 지우지 않은 이유: 저장소를 공개하면(T5) Actions가 무료라 트리거만 되살리면 된다.
- 로컬 검사는 깨끗한 환경을 보장하지 못한다. T7의 `LayoutProps` 오류가 그 예다. 타입 검사가 `next typegen`부터 돌도록 해 둔 것이 이 위험을 줄인다.
- 다른 선택지인 "저장소 공개"는 T5(PM)라 이 결정과 따로 두었다.

**확인**: 이 컨테이너에서 `python3 .github/scripts/check_all.py`를 돌려 6단계가 모두 통과했다. Windows에서는 돌려 보지 않았다.

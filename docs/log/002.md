# 002. 공개 명세를 확인하고, 데이터를 미리 수집하는 쪽으로 정했다 (2026-10-29)

> [진행 로그 인덱스](README.md) · 작성: Claude Code (PM 실시간 검토) · 관련: T2, T4, D1, Q1, Q8

**계기**: 키 발급 전에 할 수 있는 사전작업(응답 데이터 분석, API 조합 검토)의 계획을 세우라는 PM 요청. 첫 계획을 다시 검토하면서, 계획이 기대는 전제를 공개 명세로 확인했다.

**한 일**:
- 키 없이 볼 수 있는 자료로 다섯 API 중 네 개의 명세를 확인했다. 결과는 [api-survey/findings.md](../../experiments/api-survey/findings.md)에 있다.
  - 온통청년 현재 엔드포인트는 `go/ythip/getPlcy`다. 옛 주소는 홈페이지로 이동한다.
  - 복지로 두 API는 선정기준이 상세 조회에만 있다.
  - LH 15058530은 목록만 주고, 상세는 별도 API다. 응답에 자격조건이 없다.
  - 잡알리오는 목록에 신청자격·결격사유·우대조건이 있다.
- 사전 조사 계획을 [api-survey/README.md](../../experiments/api-survey/README.md)에 W1~W7로 정리했다.
- PM 승인으로 D1(미리 수집, JSON 파일 저장)을 기록하고, README 서비스 흐름을 D1에 맞게 고쳤다.
- STATUS를 바꿨다. T2에 LH 상세 API 신청을 추가했고, T6(명세 카드 스크립트)과 T7(샘플 수집)을 새로 넣었다. Q1에 기준 변경안을 적었고, Q8(의미 검색)을 새로 올렸다.

**근거**:
- D1.
- Q1 변경안의 이유: D1에서는 서버가 걸러서 LLM에 넘기므로, LLM이 받는 양은 API 응답 크기가 아니라 넘기는 정책 수와 필드가 정한다(추론). 기준 변경은 PM 승인 전이다.
- Q8: PM이 벡터 DB로 RAG 최적화를 검토 중이다. 데이터가 수천~1만 건이라 벡터 DB는 필요 없다고 봤다. 의미 검색 자체의 쓸모는 W5 비교 실험으로 정하기로 했다.
- "461건 상세 조회에 최소 5일"은 461 ÷ 100(일일 한도)으로 계산한 값이다. 한도를 세는 단위는 확인하지 않았다.

**확인**:
- 온통청년: `getPlcy`에 키 없이 요청하면 HTTP 400, `opi/youthPlcyList.do`는 302로 홈페이지 이동, 필드 설명 API(`sur/link/openApiIntro/86`)는 401이었다.
- 복지로 중앙·지자체, 잡알리오: data.go.kr 페이지에 들어 있는 Swagger JSON을 파싱했다. LH는 Swagger가 비어 있어 첨부 활용가이드 docx를 읽었다.
- 복지로 파일 데이터 15083323의 행 수와 열은 data.go.kr 페이지 메타 정보로 확인했다. CSV는 받지 않았다.
- 실제 API 응답은 받지 않았다(키 없음).

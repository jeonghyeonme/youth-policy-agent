# 002. 측정을 키 없이 미리 준비했다: API 문서 조사, 대표 질문 후보, 측정 스크립트 (2026-11-07)

> [진행 로그 인덱스](README.md) · 작성: AI(Claude Code), 작업자 요청 · 관련: T3, T4, Q2

**계기**: 남은 일이 키 발급(T2)과 PM 결정(Q2, Q5)에 막혀 있다. 그것에 기대지 않는 준비를 먼저 해 두면 키가 나오는 날 바로 잴 수 있다. 이 작업은 `archive/youth-policy` 브랜치 대상이다(main의 D1: 청년 정책 작업은 이 브랜치로 PR).

**한 일**:
- `experiments/context-measurement/api-survey.md`: 후보 API 다섯 개의 공개 문서를 읽고 응답 형식, 키 파라미터, 2단계 호출 여부, 사용자 조건 요청값, 서술형 필드를 정리했다. 온통청년 코드정의서(xlsx)를 요약했다.
- `experiments/context-measurement/question-candidates.md`: Q2 대표 질문 후보 A~D와 추천안(A+B). STATUS Q2 줄에 연결했다. 결정은 PM이 한다.
- `experiments/context-measurement/measure.py`와 테스트: 저장한 응답 파일(JSON/XML)을 읽어 원본 / 빈 값 뺀 JSON / 지정 필드만 남긴 JSON의 크기를 표로 낸다. API를 호출하지 않는다.
- STATUS: Q2 후보, 새 위험 두 개(온통청년 문서 불일치, 2단계 호출).

**근거**:
- 측정 스크립트 언어를 Python 표준 라이브러리로 했다. 제품 기술 스택(Q6)이 아니라 실험 폴더 안 일회성 도구이고, 설치할 것이 없다. Q6이 다른 언어로 정해져도 이 도구는 버리거나 그대로 써도 된다.
- 토큰 대신 UTF-8 바이트·글자 수로 잰다. 토큰 기준은 LLM 업체(Q5)에 달려 있다. 업체가 정해지면 그 토크나이저로 바꾼다.
- 목록 찾기 규칙: JSON은 dict가 가장 많이 든 리스트, XML은 같은 이름으로 가장 많이 반복되는 자식 요소. 응답 구조를 아직 몰라서 API별 경로를 하드코딩하지 않았다. 실제 샘플에서 틀리면 그때 고친다.
- 샘플 파일에 키 파라미터 이름(`serviceKey`, `openApiVlak` 등)이 보이면 재지 않는다. 요청 URL을 통째로 저장하는 실수를 막으려고. AGENTS.md "API 키".
- 대표 질문 추천: A·B가 후보 API 다섯 개를 모두 건드리고, 코드 조건과 서술형 조건을 하나씩 대표한다.

**확인**:
- `python3 -m unittest experiments/context-measurement/test_measure.py` — 5개 통과. 손으로 만든 JSON·XML 샘플로 건수, 필드 추리기, 키 섞인 파일 거부를 확인했다.
- 실제 API 응답으로는 확인하지 않음(키 없음). 목록 찾기 규칙이 실제 응답에서 맞는지는 T4에서 본다.
- API 조사는 공개 문서 기준이다. 온통청년 필드 목록 표는 JS로 그려져 읽지 못했고, data.go.kr 첨부(코드표·활용가이드·Swagger)는 열지 않았다. 트래픽 숫자는 어느 문서에도 없었다.

# 011. v5는 조문 선택이 좋아졌지만 토큰이 기준 경계라, 주제 표만 쓰는 fallback 모드를 더했다 (2026-11-01)

> [진행 로그 인덱스](README.md) · 작성: Claude Code (PM 실행, 커밋 e7c4108) · 관련: Q7, T6

**계기**: PM이 v5 결과(목차 전체 12건, 분야 목차 2건)를 푸시했다. 분야 목차 실행은 너무 오래 걸려 멈췄다고 했다.

**한 일**:
- v5 12건의 주제·조문 선택과 답을 `laws/` 원문과 대조했다.
- `two_call.py --toc fallback`: 1회차에 주제 표만 주고, 맞는 주제가 없을 때만 목차로 한 번 더 고른다.
- `trial.py` `post_groq`: Groq가 90초보다 오래 기다리라고 하면 기다리지 않고 멈춘다. 하루 한도에 닿은 경우로 본다.
- README v5 기록, 3안 비교 2.3, STATUS T6을 고쳤다.

**근거**:
- 토큰(실측): 질문당 평균 6,470, 하루 약 30개. 1회차가 약 5,000토큰이다. 목차 3,850자와 주제 표 1,918자를 함께 주기 때문이다.
- 조문 선택(실측): 12건 중 11건이 맞았다. 목차는 표에 없는 c15에서만 필요했는데 그마저 찾지 못했다. 그래서 목차를 기본에서 빼고 대비책으로만 둬도 선택 품질이 크게 떨어지지 않을 것으로 봤다(추정).
- 느린 원인(추정): 기록된 호출 시간은 1초 안팎이었다. Groq 무료 분당 8,000토큰 한도와 하루 200,000토큰 한도에 걸려 기다린 것으로 본다. 대기 시간은 기록하지 않아 확인하지 못했다.
- c10의 "제575조, 제578조" 경고는 넘겨준 제3조⑤ 원문 안에 있는 민법 참조라 오탐이다. 인용 검사는 법령명을 보지 않는다.

**확인**:
- `--fake`로 fallback 두 경로(주제 있음 → 1회차 1번, 주제 없음 → 목차로 한 번 더)와, 오래 기다리라는 429에서 저장 없이 멈추는 것을 확인했다. 주제 표만 쓰는 1회차 시스템 프롬프트는 2,182자다(실제 laws/ 기준).
- 실제 Groq로는 fallback을 돌리지 않았다.

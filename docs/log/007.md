# 007. 첫 샘플로 측정해 보니 필터링 없이는 LLM에 못 넘긴다 (2026-11-08)

> [진행 로그 인덱스](README.md) · 작성: AI(Claude Code), PM 요청 · 관련: T2, T4, D5, Q4

**계기**: PM이 로컬에서 `fetch_samples.py`를 실행해 샘플을 push했다. PM이 Groq로 진행하자고 했다.

**한 일**:
- 샘플에 키 파라미터 이름이 없는지 검사했다(없음). `measure.py`로 크기를 재고 `results.md`(1차)를 썼다.
- `measure.py` 고침: 상세 응답처럼 한 건짜리 문서를 그 안의 작은 반복 목록(문의처 등)으로 잘못 세던 문제, LH처럼 목록을 감싸는 리스트를 고르던 문제, 공백만 있는 값을 빈 값으로 안 보던 문제. 테스트 2개 추가.
- `fetch_samples.py` 고침: 잡알리오 ID 필드(`sn` → `recrutPblntSn`), 복지로 지자체 조건 완화(0건이었음), 동작하지 않는 온통청년 옛 주소 제거.
- 필드 추리기 초안 `fields/youthcenter.txt`, `fields/welfare_national.txt`.
- D5(Groq), `.env.example`의 `LLM_API_KEY` → `GROQ_API_KEY`. STATUS에서 T2(키 발급, 끝남) 삭제, T4 진행 중, Q4·Q5 갱신.

**근거**:
- 법령 API 키(`LAW_API_OC`)는 PM이 "다른 컨셉 때 쓰던 것, 안 쓴다"고 해서 `.env.example`에 넣지 않았다.
- 필드 추리기는 "코드 필드는 서버 필터링용, LLM에는 서술형과 설명만"이라는 가정이다. 구현 계획 때 다시 본다.
- 서울 필터는 `zipCd`가 `11`로 시작하는 코드를 하나라도 가진 정책으로 흉내 냈다(서울 시군구 코드 접두사).

**확인**:
- 단위 테스트 13개 통과, 링크 검사 통과.
- 숫자는 모두 `samples/`의 실제 응답으로 계산했다(실측). 건당 크기는 받은 첫 페이지 기준이라 전체 대표값인지는 확인하지 않음.
- 토큰 수는 계산하지 않았다(Groq 모델 미정).

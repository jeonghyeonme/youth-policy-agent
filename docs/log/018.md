# 018. 오류 방지 작업을 모두 했다고 보고 정확성·피해 점수를 다시 매겼다 (2026-11-01)

> [진행 로그 인덱스](README.md) · 작성: Claude Code (PM 요청) · 관련: Q7

**계기**: PM이 기준별 점수의 근거(원문 링크, 기관 재확인 등)를 보고, 세 안 모두 오류 방지 작업을 최대한 했을 때를 기준으로 하자고 했다. 대시보드에서는 "어디서 갈리나"·"사용자 쪽 비중에 따른 합계"를 빼고 근거 표를 점수판으로 바꿔 달라는 요청도 있었다(같은 날 반영).

**한 일**: [concept-scorecard.md](../reference/concept-scorecard.md) 5절을 추가하고 대시보드 점수·"오류 방지 작업" 절을 갱신했다. STATUS Q7을 고쳤다.

**근거**:
- 바뀐 점수: 청년 정확성 3 → 3.5, 피해 4 → 4.5. 법률 정확성 3.5 → 4, 피해 2 → 3. 생필품 정확성 4 → 4.5. 모두 추정이다.
- 합계: 법률 3.52, 청년 3.42, 생필품 2.92. 사용자 쪽 소계는 청년 2.52가 가장 높다. 두 안이 갈리는 사용자 쪽 비중은 70%에서 75%로 옮겨 갔다(계산).
- 법률 피해를 3에서 멈춘 이유: 원문·링크·연결을 다 붙여도 기관이 다시 확인하는 단계가 없다. 청년 정책은 신청 단계에서 기관이 자격을 다시 본다.

**확인**: 합계와 교차 비중을 손으로 다시 계산했다. 대시보드 자체 검사 결과는 확인하지 못했다.

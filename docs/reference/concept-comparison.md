### 2.1 법률 정보안의 결정적 질문: 무료 LLM으로 돌아가나

D1(생필품)·D3(청년)의 공통 제약은 **무료 LLM API**다. 청년 정책 작업에서 Groq 무료 한도는 하루 200K 토큰이고, 질문 하나에 LLM 2회·약 3K 토큰을 써서 하루 60~80개 질문이었다(실측).

법률 정보안은 구조가 다르다. 도구를 고르고, 목록을 보고, 본문을 읽고, 근거를 검증하는 루프라 질문 하나에 LLM을 4~8회 부르고, 조문·해석 본문이 매 호출 입력에 쌓인다. 질문당 15K~40K 토큰이면 하루 5~13개 질문이다(**추정**, 재지 않음). 데모·평가셋 60개 실행에도 며칠이 걸린다.

선택지는 셋이다.
1. 무료 LLM 제약을 풀고 유료 API를 쓴다 → PM 승인(비용·외부 의존).
2. 루프 횟수와 본문 길이를 제한한다(조문 단위로 잘라 넣기, 최대 호출 수 고정) → 에이전트다운 장점이 줄어든다.
3. 로컬 모델(Ollama, 제안서 6.1)을 쓴다 → 팀원 PC 성능에 좌우되고 한국어 품질 미확인.

**중간 결과 (2026-10-31, [legal-tokens](../../experiments/legal-tokens/README.md) v1·v2)**: 스크립트 버그로 법령 본문을 거의 읽지 못해 확정값이 아니다. 본문 없이도 질문당 평균 6,791토큰, 하루 약 29개로 목표 아래였다(실측, 하한으로 봄). 또 본문을 읽지 않은 답 4건이 조문을 인용했고 확인한 2건이 틀렸다(실측). 무료 소형 모델로는 "읽은 원문만 인용"을 프롬프트가 아니라 코드로 강제해야 한다. v3 재실행으로 확정한다.

**이 질문은 시험으로 답할 수 있다.** 대표 질문 3개(용어 1, 학사 규정 1, 아르바이트 절차 1)를 Groq로 돌려 질문당 토큰을 재면 된다. 청년 정책 브랜치의 `experiments/llm-providers/trial.py` 방식을 그대로 쓸 수 있다. 실제 호출은 사람이 한다(AGENTS.md).

## 3. 추천

**니즈 충족만 보면 법률 정보 > 청년 정책 > 생필품 가격이다. 4~5주·무료 LLM 제약까지 넣으면 청년 정책이 가장 안전하다.** 그래서 순서를 이렇게 제안한다.

1. **생필품 가격은 후보에서 뺀다.** 기존 서비스(참가격 장바구니 비교)와 차이가 작고, LLM이 할 일이 적어 원래 목표(LLM 에이전트 학습·포트폴리오)에 맞지 않는다. D1의 이유("니즈가 좁고 날카롭다")는 수치 근거가 없었고, D1 스스로 "어떤 타깃에도 쓸 만한 기능이 없으면 다시 본다"고 적었다.
2. **법률 정보를 1순위로 두되, 축소판 + 토큰 시험을 조건으로 건다.**
   - 축소 범위: 생활법령·법률용어 + 노동·아르바이트 + 학사 규정(시연 대학 1~2곳). 개정 비교·판례·자치법규·웹 검색은 확장으로.
   - 시험: 위 2.1의 토큰 측정. 하루 30개 질문 이상이 나오거나 PM이 유료 LLM을 승인하면 확정한다.
   - 이름은 "법률 상담"이 아니라 "법률 정보 안내"로.
3. **시험이 실패하면 청년 정책으로 돌아간다.** 사전 조사·공통 형식·LLM 시험이 이미 있어 손실이 가장 적다.

두 안을 합치는 것(청년 정책 + 노동·주거 법률 정보)은 대상 사용자가 같아 그럴듯하지만, 출처와 LLM 구조가 달라(필터형 2회 호출 대 탐색형 루프) 4~5주 안에 둘 다 완성도를 내기 어렵다. 추천하지 않는다.

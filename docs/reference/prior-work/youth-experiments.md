## 질문→답 실측 y1 (2026-11-01, 질문 10개)

- 토큰: 답을 낸 8건 평균 **3,540**(지금 `main` 실측 약 6,100 — 그쪽은 2회차에서 3개만 설명, 지금은 8건을 모두 판정한다).
- 형식 오류: 10건 중 **2건**이 2회차 JSON 검증 실패(빈 출력). 재시도가 필요하다고 적었다.
- 정책 선택: 고른 21건 중 **약 17건**이 질문에 쓸모 있음. 답을 낸 8건 모두 쓸모 있는 정책을 1개 이상 냄.
- 설명 오류: 자격 조건이 비어 있을 때 "제한이 없다"로 읽은 표현이 여러 건. 타지역에서 돌아오는 청년 대상 정책(고향올래)을 그 지역 거주자에게 맞다고 설명.

## 서버 필터 점검 (2026-11-01, LLM 없이)

- 분야·지역·나이·마감으로 걸러도 질문당 **89~728건**이 남았다(지금 `main`의 질문 A 실측 약 250건과 같은 결론).
- 단순 키워드 순위로는 상위 3건 중 맞는 정책이 평균 **약 0.8건**. 같은 정책이 출처·연도별로 겹쳐 나왔다(지금 `main`은 log/030에서 중복 제거를 넣었다).

## 지금 구현에 가져다 쓸 후보 (T10 품질 점검 때 시험)

1. **2회차 JSON 형식 오류 재시도**: 그쪽 실측 10건 중 2건. 지금 `main`은 형식 오류면 502로 끝난다.
2. **"정보 없음"과 "제한 없음" 구분**: 자격 칸이 비어 있으면 "조건이 적혀 있지 않다"로 말하게 한다(판정 프롬프트 규칙).
3. **신청할 수 없는 정책 사업 거르기**: 온통청년에 "위원회 설치", "시스템 시범 설치" 같은 사업이 섞여 있다. 지금 `main`은 LLM이 "불가"로 거르는데, 서버에서 먼저 거르면 토큰을 아낀다.
4. **"타지역에서 돌아오는 청년" 같은 대상 조건**: 지금 `main`도 귀환 청년 주거지원을 "확인 필요"로 냈다(log/030). 같은 종류의 오류다.
